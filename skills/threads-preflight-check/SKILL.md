# Threads Preflight Check

這個 skill 是給「準備發脆之前」的最後一道健檢。

它不負責幫你直接寫文，也不直接 publish。它的工作是先回答：

1. 這篇有沒有硬性風險？
2. 這篇跟你最近幾篇會不會太像？
3. 這篇是不是正在撞同一個主題 cluster？
4. 這篇如果現在發，會不會因為多樣性不足被壓？

---

## 何時用

以下情況先跑這個 skill：

- 使用者說「幫我看這篇脆能不能發」
- 使用者說「發文前健檢」
- 使用者說「這篇會不會限流」
- `daily-threads-post` 準備把草稿拿給使用者確認之前
- 任何要呼叫 Threads publish API 之前

---

## 跟其他 skill 的分工

- `threads-preflight-check`
  - 做發前健檢
  - 看字數、紅線、相似度、主題密度、多樣性、CTA 重複、hook 對齊
- `threads-algorithm-rules`
  - 當作規則母庫
  - 尤其是紅線 R1-R12 與信號 S/P/A 的定義
- `daily-threads-post`
  - 負責產草稿與實際發佈流程
  - 產稿後一定先經過這份健檢
- `threads-publishing-rules`
  - API 與媒體格式限制
  - 尤其是 500 字、token、影片 host、mp4 規格

順序固定：

1. 先讀 `daily-threads-post` 的格式硬約束
2. 再跑本 skill 做發前健檢
3. 再用 `threads-algorithm-rules` 做紅線複核
4. 全過關才進 publish

## 需要的資料

### A. 最佳情況：有近期貼文資料

優先使用近期 **原創** Threads 貼文，不要把 `REPOST_FACADE` 當成原創樣本。

可接受來源：

- 本機 `.env` 的 `THREADS_ACCESS_TOKEN`
- 使用者提供的近期貼文清單
- 使用者貼上的貼文連結或全文

若能走 API，至少看最近 5 篇原創，理想看最近 10 篇。

### B. 次佳情況：只有單篇草稿

如果拿不到近期貼文，仍可做單篇健檢，但必須明說：

- 可做字數、紅線、hook 對齊、主題混雜檢查
- **不能**對同主題密度、相似度、多樣性做高信心判斷

## 執行流程

### Step 1. 先確認這次檢查的是什麼

先收斂到這 5 個資訊：

1. 草稿全文
2. 媒體型態：純文字 / 圖 / 影片 / 輪播
3. 這篇想拿什麼互動：留言 / 分享 / 收藏 / 導流
4. 是否有外連結
5. 是否能取得近期原創貼文

如果草稿還沒寫完，不要假裝能做完整健檢。

### Step 2. 先做硬性檢查

#### 2.1 字數

- 直接算全文字元數
- Threads API 上限是 **500 字元**
- 超過就列為 `BLOCKER`

#### 2.2 單一主題

檢查是否只有一個主題中心。

常見失敗：

- 前半在講工具更新
- 中間插一段個人經營心得
- 結尾又轉去推另一個產品或影片

如果前兩句無法清楚回答「這篇到底在講什麼」，列 `BLOCKER` 或 `WARN`。

#### 2.3 Hook 與正文一致

檢查首句承諾跟後文是否兌現。

常見失敗：

- 標題像警告，正文卻只是資訊整理
- 標題像完整教學，正文其實只有觀點
- 標題點名 A 問題，正文主要在講 B

#### 2.4 CTA 類型

把 CTA 分成四類：

- 留言型
- 分享型
- 收藏型
- 導流型

檢查 CTA 是否過於硬推、像 bait，或最近幾篇都用同一種 CTA。

### Step 3. 跑演算法紅線

讀 `skills/threads-algorithm-rules/SKILL.md`，至少掃以下項目：

- R1 Engagement bait
- R2 Clickbait
- R3 首句與正文不一致
- R4 明顯搬運 / 低品質原創
- R5 連續同主題
- R6 低品質外部連結
- R8 負面回饋觸發
- R9 主題混雜
- R11 圖文不一致
- R12 軟性降權

本 skill 不重抄母規則，直接把這份當準則。

### Step 4. 做近期相似度與主題密度檢查

這是本 skill 的核心。

如果有近期原創貼文，對照最近 5-10 篇，判斷：

#### 4.1 主題 cluster

先用人能理解的方式幫每篇貼標：

- 主體：在講哪個產品 / 平台 / 問題域
- 情境：警告 / 教學 / 補救 / 評論 / 實測 / 工具清單
- 受眾：新手 / 已使用者 / 開發者 / 非技術者
- 目的：回留言 / 拿分享 / 拿收藏 / 導流

#### 4.2 近似風險分級

用以下規則分級：

- `GREEN`
  - 同領域但不同問題
  - 或同主體但受眾、結論、情境已明顯切開
- `YELLOW`
  - 同主體且同受眾
  - 但切角不同，仍有新資訊
- `RED`
  - 同主體 + 同受眾 + 同問題
  - 或只是把前一篇換句話說
  - 或 48 小時內連發同一事件的延伸補充

#### 4.3 多樣性不足

檢查最近 3-5 篇原創是否出現：

- 同一產品連續講
- 同一事件連續講
- 同一 CTA 類型連續用
- 同一 hook 模板連續用

命中 2 項以上，至少列 `WARN`。

#### 4.4 爆文後續篇風險

如果近期有一篇明顯高表現貼文，現在這篇是它的：

- 補充篇
- FAQ 篇
- 延伸篇
- 另一個角度重講

要額外提醒：

- 這種內容對老讀者有價值
- 但對推薦系統可能被判成同 cluster 延伸
- 需要切出新的問題意識，而不是只做補完

### Step 5. 做相似度判斷時的實務標準

不要只看字面是否重複，要看這 6 個維度：

1. 主體是否相同
2. 受眾是否相同
3. 問題是否相同
4. 結論是否相同
5. CTA 是否相同
6. 發文間隔是否過近

如果其中 4 項以上相同，視為高相似。

即使字句不同，也不能因為「不是逐字重複」就判低風險。

## 輸出格式

輸出一定要短，不要寫成論文。固定用這個格式：

### 1. 結論

- `可發`
- `可發，但建議先改`
- `先不要發`

### 2. 風險燈號

- `BLOCKER`
  - 超過 500 字
  - 紅線命中
  - 與近 48 小時貼文高度重複
- `WARN`
  - 同主題密度偏高
  - CTA 類型重複
  - 多樣性不足
- `GOOD`
  - 哪些地方是安全或有優勢的

### 3. 相似度判斷

固定回答：

- 最近最像的是哪一篇
- 相似點是什麼
- 差異點夠不夠大
- 這篇現在發會不會撞 diversity

### 4. 最小修改建議

只給 1-3 個最有用的修改，不要重寫整篇，除非使用者要求。

---

## 判斷原則

- 不要把「同領域」誤判成「同篇重發」
- 不要因為一篇資料量大就以為它有新角度
- 不要只看字面不看語意
- 不要只看文字，不看媒體型態與 CTA
- 沒有近期資料時，要直接說信心不足

---

## 快速口訣

- 同領域可以，同問題不行
- 同主體可以，同結論連發不行
- 爆文可以續，但不能立刻換皮重講
- 先過 500 字與紅線，再談潛力
